# Editorial website design guide

Status: owner-approved visual direction, implementation pending s114. Source: the October 15 website-first-v7 preview and owner screen recording. This is the website-wide target; existing app contracts remain effective until each surface is migrated and verified.

## Identity and tokens

Warm, quiet editorial presentation for freelancers and small studios. Lead with the recurring client-update burden, then demonstrate the solution. Use cream paper `#f7f3e9`, ink `#142024`, deep teal `#287f7c`, subtle dividers `#d9d3c6`, muted text `#4c5552`. Use opaque surfaces and readable focus borders; check contrast in actual combinations. Keep semantic success, warning and error tokens from the app system. No global replacement that makes status colors ambiguous.

Georgia/Times serif for marketing display headings; system sans for controls, long prose and application data. Preserve the existing app font for forms and tables. Display weight 500, tight but legible tracking around -0.045em, line height 1.08. Desktop hero approximately 44–68px with responsive sizing; mobile approximately 29–40px. Never shrink long visitor text to unreadable sizes: bounded single-line fields should scroll internally when necessary. Body 16–18px, line height 1.5–1.65. Hero has exactly three explicit lines; no one-word orphan generated by responsive wrapping.

Content width up to 1400px, 5–6% side gutters, section spacing 56px mobile / 88–96px desktop. Two-column illustration/text sections collapse to one column. Flat dividers, 3px marketing button radius, no gratuitous shadows or glass panels. Application dialogs, controls and popovers keep their documented functional radius and layering rules.

## Artwork

Reuse approved cream/teal editorial assets, including `01-hero-v2-hand-correction.png`; never the anatomically incorrect original. Desktop artwork sits to the right with clear text space; mobile artwork follows text. Illustration is conceptual, never a product screenshot or customer testimony. Optimize raster assets with intrinsic sizes and responsive formats; do not ship the uncompressed gallery masters as page backgrounds. Hero image is priority; lower illustrations lazy-load. Alt text describes meaningful content; decorative images get empty alt.

## Hero and demonstration

Initial lines: “You built the site.” / “Now you’re stuck” / “updating it.” Supporting copy: “Let clients edit the words. Make time for the work that matters.”

One automatic sequence: a small 17px pointer follows a slow curved path, pauses over “site”, reveals a dashed teal outline, clicks, shows selection/caret, types “website”; moves away and returns along a curved path to “stuck”, then types “done”. Never loop indefinitely. Respect reduced motion. Stop immediately on visitor focus/pointer/typing, tab hidden, or unmount; never replace visitor text after interaction. Avoid hijacking scrolling. Use accessible plaintext editing on three headline lines and supporting copy; no font editing, visible hint, replay or reset button. Reload restores original content. No storage, API writes, analytics payloads containing edited text, or customer-domain edits.

Directly below the hero place the existing functional InteractiveHero demo, not a screenshot, animation substitute, iframe of the whole demo route or merely a link. Keep /demo working independently. Separate the local hero illustration/animation from the real interactive demo. No fake save/publish claims.

## Components and page families

Shared editorial navigation/footer must retain login state, signup, pricing, demo, tools, comparisons, install docs, legal links and cookie settings. Compose from existing ui primitives. Pricing remains catalogue-backed, with the same founding-offer semantics, loading/error handling and checkout behavior.

Marketing pages use editorial headings and generous space; tools use compact controls and clear results; blog/legal/install content use readable article measure; auth uses restrained branded framing; dashboard uses the palette and typography hierarchy without inserting illustrations into working forms, tables or permission dialogs. The installed customer widget retains its independent compatibility boundary.

## Writing and states

Personal and concrete: requests, interruptions, handoff, responsibility. No invented results, customers, savings, revenue or universal integration claims. Explain errors with next steps. Preserve loading/empty/error and disabled states; hover never replaces keyboard focus. Touch and keyboard users can edit. Escape blurs an edit; Enter cannot add headline lines; paste is plain text; IME/composition and selection must be tested.

## Rollout

s114: homepage, retained /product page, real demo placement and design foundations. Follow-on route groups: demo/try/install; comparison/tools/report surfaces; blog/legal; auth/settings/dashboard. Inventory and migration order live in the s114 research file. Do not claim website-wide migration from a homepage release.
