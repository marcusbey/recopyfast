s66c — One page per site, and one clear way to give access

Owner, 2026-10-07: “/dashboard/sites is overwelming … invite a client, and editors are confusing. which one to use and when ?” Owner, 2026-10-08: “u need to have subpages to it. steps for user with advanve or quick setting.” This mockup shows the light Sites list, the site's four subpages (Overview with Quick setup, Install, People & access, Settings), the two access dialogs, and the click counts. Each page is shown at 1280 and at 375. Values come from docs/design-system.md (s66a) and s66b1's PageShell contract (ADR 053).

Sites · Overview · Done state · Install · People & access · Settings · Dialogs · Click counts

1 · Sites — a light list

  • One row per site: name (link to the site page), domain, status, last edited, one primary action chosen by status (Awaiting install → Continue setup; Live/Stale → Edit website) and ⋮, visible at rest.
  • Gone from the face of the card: Edits/Views/Activity metrics (on the Overview; Views is never computed), hover-only Copy domain, View Details, the mislabelled Settings, the share icon (now in ⋮).
  • No Table primitive (gap 8): a <ul> of border-b rows in one bordered panel. Below 768 the row stacks; ⋮ stays top-right.

2 · Site Overview — Quick setup (s66c2), step 2 active

  • PageShell: h1 = site name, meta = StatusBadge, description = domain ↗, actions = Edit website · Version history, nav = SiteSubnav (links, aria-current, push history).
  • Quick setup replaces ActivationChecklist (same useSiteActivation data and dismissal). Every step's state comes from the server, so it resumes where the owner left off. The live status row flips on the provider's 5-second poll, with no reload.
  • s66c1 interim (not drawn): the existing checklist, relabelled to Add editor and Edit website, sits in place of this panel.

  • When the site goes live, the header turns success-toned. Step 3 stays offered until it is done (an editor with Publish added, or an edit published) or the owner hides it. Then the panel leaves the page.

3 · Install

  • The snippet appears exactly once on the page, in every install state: live and stale no longer hide it behind “View install snippet”. The recipe tabs carry text only.
  • Site token: CodeBlock + Regenerate snippet (same confirmation, same POST). A regeneration updates every subpage at once, because there is one site record (ADR 052).
  • Domain ownership moved to Settings: it is optional and blocks nothing.

4 · People & access

  • Exactly two actions, each with a one-line explainer that says when to use it. The Add editor copy does not promise publishing: the form defaults to View+Edit.
  • Below: the two lists, each under its own heading with a count. Preview links moved out of the dialog: usePreviewLinks + ShareLinkCard.
  • The 60-character label wraps or ellipsizes inside a minmax(0,1fr) track (s66a dialog rule, applied on the page).

5 · Settings (advanced)

  • The “advanced” path: nothing here is needed to start editing. Name and domain are read-only, because there is no rename or domain API (separate API story).
  • API keys arrive in s66c2 (ApiKeysPanel siteId). The import/export tab “History” becomes Operation history.
  • Danger zone: the same DELETE and the same confirmation. On success the app navigates to Sites with replace, and the creator-only 403 shows in the dialog.

6 · Dialogs and the row menu

  • Add editor is one component (AddEditorDialog) behind the People action, the checklist step and Quick setup step 3. Those last two pass the View+Edit+Publish preset. On success the body shows the delivery notice (or the editor-hub fallback), and the footer shows Done.
  • Share preview link is create-only now. View is the only permission ticked by default, and the grant resets to View after each send. The s68c 409 for a removed editor renders in its Alert.
  • Edit website has no dialog any more. It opens the new tab on click (popup-safe), and errors render inline as an Alert. The pill-shaped raw button and the emerald DOM toast are deleted.
